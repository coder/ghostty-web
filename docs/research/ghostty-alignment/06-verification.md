## Executive summary

The four saved reports (01–04) are, on the whole, accurate and carefully classified; report 05 was not available during the original pass; the completed follow-up and its re-runs are recorded in §7. The core reproduced defects hold up when re-tested with different stimuli. A 24-link random sample of commit-pinned upstream citations pointed at the claimed symbols, and an automated check found every cited upstream path and line range inside its file. The problems found are mostly about **attribution, reproducibility and core-versus-host scope**. Few headline claims are wrong.

1. **RT-01 (crash after `reset()` or dispose plus create) is real and is the most severe finding [R].** This review reproduced it with fresh triggers:
   - **Trigger:** combining marks, Thai, ZWJ emoji or VS16, then `reset()`, then a write.
   - **Controls (no trap):** ASCII, single-codepoint CJK, a grapheme erased before reset, in-band RIS, and a second terminal created before the first is freed.
   - **Backport:** the complete `420de124f` backport removes every trap.
   - **After a trap:** in one follow-up, the trapped terminal threw on every later write while other terminals on the instance kept working.

   The audit (report 01) missed RT-01; a post-review note now points to it.

2. **New: the page-zeroing backport also fixes the stale-row bug that the patch's `Screen.zig` edit works around [R].**
   - **Result:** pinned + patch _without_ the `Screen.zig` hunk but _with_ `420de124f` gives 0/30 stale-row failures (two runs, versus 6/30 without it). `lib/viewport-corruption.test.ts` and all 356 `lib/` tests pass against that build; the same test fails without the backport.
   - **Implication:** one upstream backport can replace a local core divergence.
   - **Caveat:** this covers one stimulus; whether other row-recycling paths (upstream `b31fbc846`) are covered was not tested.
3. **New: no tagged release has the terminal C API or the pinned-core fixes [S].**
   - **v1.3.0 and v1.3.1:** the same 50 `lib_vt` exports as the pinned commit, no `include/ghostty/vt/terminal.h`, `minimum_zig_version = 0.15.2`.
   - **Fixes present in the tags:** the `linkCells` fixes (`5a2f5a6b9`, `26b104c9e`) and `86d5048da`.
   - **Fixes absent from the tags:** `420de124f` (RT-01), `e6db5b633` (SW-01), `5fa37f2b7` (SW-02), `815ccb060`, `492c26067` (WASM memory pool) and `b31fbc846`.
   - **Patch on v1.3.1:** the patch applies textually apart from its `.gitignore` and `Screen.zig` hunks, but fails to compile (2 errors in the patch's handler: semantic-prompt actions were renamed). Even a tag bump needs patch porting.
   - **Consequence:** "rebase onto upstream" in reports 02 and 03 means pinning untagged `main` with Zig 0.16 until a tag ships the API.
4. **The backport recipe in report 04 was not reproducible as saved [R].** `p04-zerofix-backport.diff` contains only the `builtin` import, because upstream's hunk does not apply to pinned context. This review wrote the complete three-hunk diff (`probes/06-verify/v06-zerofix-full-backport.diff`). It rebuilds report 04's validated artifact **byte for byte**, so report 04's results stand; the recipe is corrected.
5. **One performance attribution was overstated [M].** Report 03 attributed most of the gap between report 02's 0.70 ms (Bun, full 200×50 decode) and its own 0.21 ms to `DataView` versus `Uint32Array`. Changing only that in report 02's harness gives **0.54 ms**, so the decoder explains about a third of the gap. The conclusion (a packed row export is optional) is unaffected.
6. **Some core/host distinctions were missed, plus one platform blind spot [S][C]:**
   - **Clipboard reads:** on current, `clipboard_read` must be answered synchronously, but browser clipboard reads are asynchronous. Report 03's statement that "every other effect can be queued" is therefore false.
   - **macOS keys:** `macos_option_as_alt` is accepted but does nothing in WASM, because the encoder's macOS branches are compile-time gated. Report 02 had recommended setting it.
   - **Focus reports:** the initial focus report when a program enables mode 1004 comes from native termio, not the core.
   - **OSC 8 URIs:** `ghostty_grid_ref_hyperlink_uri` is missing from the documented "interactive" subset.
7. **Hygiene [S]:**
   - **Report 02:** one broken intra-report anchor (`#92-full-frame-extraction-cost`), now fixed.
   - **Report 01:** a stale export count (26; actual 28), now fixed.
   - **`baseline-validation.md`:** fails `prettier --check` on table alignment only. It belongs to the parent and was not edited.

All material corrections are applied in place and listed in [§3](#3-material-corrections-applied-in-place). Pre-correction copies are in `probes/06-verify/pre-correction/`.

## 1. Scope and method

- **Read-only source review:** every high-priority claim in [01](01-web-audit.md), [02](02-upstream-architecture.md), [03](03-state-and-wasm.md) and [04](04-rendering-and-text.md) was traced to the cited ghostty-web lines, patch lines, or pinned/current upstream lines. This covers ranked defects, API-availability statements, ABI proposals and performance headlines.
- **Independent probes:** where a claim was [R], it was re-run with a **different stimulus or code path**, not the specialist's own script. Examples: the public `Terminal`/`GhosttyTerminal` wrappers instead of raw exports, other Unicode triggers, and added controls.
- **Re-runs:** where an exact re-run was the only way to test a disagreement, the specialist's script was re-run and the output saved separately (`v06-*-rerun.*`).
- **Disposable builds:** two Zig 0.15.2 `lib-vt` builds in new scratch worktrees (`build-v06-zerofix`, `build-v06-noscreenfix-zerofix`), to test the backport and its interaction with the patch's `Screen.zig` edit. Nothing was built in the project or its submodule.
- **Mechanical checks:** `v06-linkcheck.py` checks every relative link and anchor. For every `github.com/ghostty-org/ghostty/blob/<sha>/<path>#Lx-Ly` link it confirms the SHA is 40 hex, the path exists at that SHA, and the range is within the file. It also checks that every repo-relative `lib/…:a-b` citation is within the file. `v06-citation-sample.txt` is a seeded random sample of 24 upstream links, read by hand for semantic match.
- **Formatting:** Prettier (repo `.prettierrc`) on every report after edits.

Not done: no browser re-runs (report 04's Chromium 155 / Playwright and report 05's Chrome 153 results are taken as reported), no native Ghostty app build, no ReleaseSafe WASM build.

## 6. False positives and existing mitigations reviewed

No ranked defect in 01–04 was found to be a false positive. These items were checked specifically because existing code might have mitigated them:

- **Ctrl+V "eaten" (WEB-07)** is deliberate: `lib/input-handler.ts:387-391` returns without `preventDefault` so the browser's paste event fires. 01 already says so. It is a policy choice that differs from native Linux (`Ctrl+V` → `0x16`, paste on `Ctrl+Shift+V`), not an accident. The right fix is a configurable platform keymap.
- **`attachCustomKeyEventHandler` polarity** (`true` = consumed) is documented in the JSDoc (`lib/terminal.ts:855-858`). It is a documented **xterm.js incompatibility**, not an undocumented bug; report 05's L05 probe and its classification are discussed in §7.
- **Bell/title heuristics (WEB-03)** are acknowledged in code comments (`lib/terminal.ts:569-589`) as workarounds for missing WASM events. The defect is real; the comments confirm intent.
- **Scroll-to-bottom on output (WEB-09)** is commented as "xterm.js behavior" (`lib/terminal.ts:580-583`). Native's default is `scroll-to-bottom = keystroke, no-output` (pinned [`Config.zig#L837`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/config/Config.zig#L837)), so 01's divergence claim stands either way.
- **`window.open` of OSC 8 URIs (WEB-14)** already passes `'noopener,noreferrer'` (`lib/providers/osc8-link-provider.ts:102-107`). Report 05's standalone-page Chrome 153 headless probe, using the same feature string, produced an inert `about:blank` popup for a `javascript:` URI; an empty feature string let it run in the opener's origin. This is not an end-to-end test of ghostty-web's link providers. WEB-14's security severity (Low–Medium, "unverified") is consistent with that. Treat it as hardening plus missing embedder policy, not a demonstrated script-injection bug.
- **`ghostty_paste_is_safe`** is exported but unused (01 WEB-12): confirmed by `grep -rn paste_is_safe lib/` (no hits). It is not a mitigation.
- **The RT-01 trigger in `reset()`** is avoided by in-band RIS (V-07), which is already recommended in 01, 03 (in-place reset) and 04.

  - **C01 (OSC 52):** writes are delivered; a denied read replies with an empty `OSC 52`; an allowed read is answered synchronously with base64.

    - `CSI 21 t` gets no reply by default.

### Publication reconciliation with report 05

## 9. Reconciled disagreements

- **WEB-02 "1,116 lines" (01) vs "566–1,154" (03).** Both are correct observations: 01 sampled one phase of the prune cycle. Resolved in 01 with a note.
- **WEB-01 severity (01 "High") vs RT-13 (04: drawing dominates).** The extraction fix removes about 5.9 ms per forced 200×50 frame in Chromium (software GPU), roughly 12–15%. It is necessary but not sufficient. Both reports now say this.
- **Exporting pinned `linkCells` (02 and 04: "with the fix") vs 03 ("rejected").** Exporting it is safe only with both `5a2f5a6b9` and `26b104c9e` backported. 03's alternative (per-frame link ids computed in the patch) avoids depending on pinned `linkCells`. Prefer 03's approach at pinned, and upstream `linkCells`-equivalent support after rebasing.
- **Packed row export (02 "motivated" vs 03 "optional").** It stays **optional**: JavaScriptCore numbers moved by 0.15–0.5 ms depending on harness details, and 04 shows extraction is under 1 ms against tens of milliseconds of drawing.
- **Patch `Screen.zig` edit (02 "valid fix, drop on rebase").** Still valid. V-01 adds that the upstream backport covers the same stimulus at pinned, so the local core divergence can be replaced now.

## 10. Residual limitations and confidence

- **High confidence:** RT-01 and its fix; V-01 (deterministic stimulus, two runs, controls in both directions); export inventories; tag contents; the static anchors in §2.
- **Medium:** core/host distinctions taken from headers and comments (V-04, V-05) and not exercised in a browser. The macOS compile-time gating is certain from source; its user-visible effect on a Mac browser was not observed.
- **Not re-verified:** browser pixel results (04), Chrome navigation results (05), throughput numbers (02 §9.1), the Unicode corpus (04 RT-10), and SW-04 backport applicability.
- **Single-stimulus caveats:** V-06 (bystander survives) and V-01 (one corpus) each rest on one stimulus.
- **Performance:** every timing here is a WASM-only micro-benchmark on one shared machine (AMD EPYC 9575F, Linux 6.8). None is a renderer or browser benchmark, and none promises a speedup.
