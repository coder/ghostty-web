## Executive summary

1. **Every saved 05 probe reproduces exactly.** L01–L13, C01–C09 (Node and Bun) and the feature-subset C02 failure re-ran byte-identical; the Chrome `window.open` probe gave the same result [R]. What some probes actually test needed correcting (§1).
2. **Most input defects are TypeScript defects, and the pinned encoder can already do the work.** Given options and an unshifted codepoint, the pinned key encoder emits Alt prefixes, Kitty sequences and release events correctly (`ESC b`, `ESC[99;5u`, `ESC[97;1:3u`) [R]. The patch is missing only getters (Kitty flags, modifyOtherKeys, Shift-capture).
3. **New, user-visible: Alt is dropped on Linux and Windows.** Alt+b sends `b` and Alt+. sends `.` [Rh]. Only DECCKM is synced into the encoder, while mode 1036 (Alt sends ESC) defaults to on. The fix is coupled to macOS: Option+a/Option+b send **nothing** today, and syncing 1036 alone would turn Mac Option-typed text such as `@` into `ESC @`.
4. **The key wrapper is lossy.** `KeyEncoder.encode` drops `unshiftedCodepoint`, `consumedMods` and `composing`. It also frees the UTF-8 buffer before encoding, although the C API only borrows that pointer. This is latent: it was not reproduced [S].
5. **Mouse findings hold, with one new ordering constraint.** Every mouse fix is possible in JS except one: the patch's `setMode` never updates `flags.mouse_event`/`mouse_format`. A getter for those flags (07 P2-5) would therefore return stale defaults unless the handler is fixed first [S].
6. **Output is not byte-preserving.** `onData` is a string. X10 mouse reports past column 95 are raw non-UTF-8 bytes in native and in current libghostty-vt [R]. xterm.js sends such reports through `onBinary`; ghostty-web has no binary channel, and the demo transport re-encodes them as UTF-8.
7. **Protocol replies: the pinned patch answers only DSR/DA, current answers the rest.** Current also gives identical effects for any chunking [R]. Its callbacks are synchronous and non-reentrant, so the adapter must queue replies and decide clipboard reads synchronously (deny by default).
8. **Security and policy gaps.** Paste does not strip controls. Link opening has no scheme policy. The copy fallback leaves copied text in the IME textarea [Rh]. Replies ignore `disableStdin`, which lets read-only viewers inject replies into a shared PTY [Rh][D].
