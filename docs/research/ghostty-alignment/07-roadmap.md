## Executive recommendation

1. **Ship the crash fix first, as an upstream backport inside the existing patch.** RT-01 [R, reproduced independently by 04 and 06]: after `reset()`, or after disposing one terminal and creating another on the shared instance, text that held combining marks, Thai, ZWJ emoji or VS16 makes the next write trap with "Out of bounds memory access". The cause is pinned `PageList` skipping page zeroing in non-safe builds ([P `PageList.zig#L340-L344`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/PageList.zig#L340-L344)), fixed upstream in [`420de124f`](https://github.com/ghostty-org/ghostty/commit/420de124f04aa322bf250098cc62d7195db94bfd). Report 06's complete three-hunk backport rebuilds report 04's validated artifact byte for byte: 0 traps and 356/356 `lib/` tests [R]. Effort XS. Keep the patch's `Screen.zig` hunk in that PR and drop it later behind a gate (V-01 shows the backport alone fixes the one stale-row stimulus tested).
2. **Order: a bounded pinned-patch extension first; current libghostty-vt is the declared target and is prototyped in parallel behind one TypeScript adapter.** Migrating first is not justified yet:
   - No tagged release has the terminal API, so migrating means pinning untagged `main`, moving to Zig 0.16, rewriting `scripts/build-wasm.sh` (the `lib-vt` step no longer exists), and shipping 1.7–2.3× the WASM gzip size (124,151 B now; 213,397 B for the documented "interactive" subset, which lacks `ghostty_grid_ref_hyperlink_uri`; 285,349 B for the full current build) [S][R].
   - Upstream documents the API as unstable ([C `vt.h#L10-L11`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/include/ghostty/vt.h#L10-L11)).
   - ghostty-web has never run on it. Only raw exports were probed in Node and Bun (02 §8, 05 probes C01–C09) [R].
   - Most high-severity, user-visible defects are TypeScript defects that need fixing on either backend (WEB-05, 06, 07, 10, 12; RT-04, RT-05) [R/RB].

   Pinned Zig additions are thrown away at migration, so cap them at cheap, high-value items: effects and replies, configuration, mode getters, in-place reset, and an ABI handshake (I-08). Exporting frames and the viewport from the pinned core (I-09) is **conditional** on a migration checkpoint (C1, §6). **Migrate earlier** if any of these holds:
   - a release tag ships `include/ghostty/vt/terminal.h`;
   - the libghostty-vt prototype passes gates G1–G7 (§6.5);
   - pinned would need non-trivial core ports, for example the row-recycling (`b31fbc846`), memory-pool (`492c26067`) or parser-speed (`87f69a12e`) fixes, none of which applies textually to pinned (§1.2).

3. **Target architecture: the Ghostty core owns terminal state; browser TypeScript owns policy, platform integration and pixels** (§2). Today TypeScript re-derives viewport, selection, colours, cursor style, link identity and replies from a lossy per-call snapshot, and that is where most fidelity bugs come from (01 executive summary).
4. **Rendering: fix Canvas2D correctness before adding new technology.** In Chromium (software GPU), a forced 200×50 frame took 51.9 ms; the WEB-01 extraction fix removes about 12–15% of that (6.4 ms at DPR 1), and drawing is most of the rest (04 RT-13) [M, one engine]. Do not start a Worker or WebGL2 renderer until the harness (I-06) shows that Canvas2D misses budget on real hardware.
5. **Measure before optimising, and gate decisions on measurements.** Build the browser pixel/frame-time harness and the differential VT harness (§7) before any performance or migration decision. This roadmap promises no speedups.

## 2. Target architecture and state ownership

```text
 Browser host (TypeScript)                                Core (WASM, Ghostty Zig)
 ┌───────────────────────────────────────────┐            ┌──────────────────────────────────────┐
 │ Terminal facade (xterm.js-compatible API) │            │ Terminal + Stream + handler          │
 │ Transport, write queue (time-sliced)      │──write────►│  modes, screens, pages, reflow       │
 │ Policies: scroll-on-output, wheel order,  │            │  viewport pin, tracked selection     │
 │  Shift override, paste confirm, clipboard,│◄─events────│  replies (DSR/DA/DECRQM/XTVERSION…)  │
 │  link opening, bell, focus-on-1004,       │ (1 drain   │  effects (bell, title, pwd, OSC 52,  │
 │  macOS Option/Cmd keymap                  │ per write) │  notifications, sync output)         │
 │ Renderer: metrics, colour/cursor/         │◄─frame─────│ RenderState: dirty rows, tagged      │
 │  decoration policy, runs, sprites,        │ (1 update  │  colours, styles, graphemes, cursor, │
 │  Canvas2D (later optional WebGL/Worker)   │ per frame) │  row ids, link keys, scrollbar       │
 │ Input: DOM events → KeyInput/MouseInput   │──encode───►│ key/mouse/focus/paste encoders       │
 │ IME textarea, accessibility mirror,       │            │  configured from terminal state      │
 │ render loop (parks when idle)             │            │                                      │
 └───────────────────────────────────────────┘            └──────────────────────────────────────┘
             ▲ CoreBackend adapter: "pinned v2" implementation now, "libghostty-vt" implementation later ▲
```

**Rules** (from 03 §6.1 and §6.3, adopted):

1. **State lives in the core; policy lives in JS.** No numeric row index outlives a mutation; long-lived positions are tracked pins/grid refs or opaque ids.
2. **One crossing per concern.** One frame call per animation frame and one event drain per write. No per-row or per-cell calls on hot paths: per-cell calls measured 15–20× a bulk read (02 §9.2).
3. **Borrowed memory** is valid until the next mutating call. Views are re-created after every export call ([C `wasm.h#L39-L48`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/include/ghostty/vt/wasm.h#L39-L48)).
4. **Exactly one render-state consumer** per terminal and one `update` per frame; getters never update implicitly ([P `render.zig#L630-L647`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/render.zig#L630-L647)).
5. **One owner object per terminal handle.** Subsystems hold the owner, never a raw handle (WEB-05).
6. **A trap poisons the terminal.** Surface `onFatal` and recreate. Treat the instance as suspect until the M7 isolation question is settled: 06 V-06 saw only the trapped terminal fail, in one probe.

## 5. Proposed contracts (PROPOSED; none of this exists)

Report 03 §6 gives a detailed layout. This section records the decisions the roadmap depends on and how they map onto both backends.

### 5.1 ABI identity and negotiation

- **Names.** Every ghostty-web-owned export uses the `ghostty_web_` prefix. Upstream-named exports are only ever upstream's own.
- **Fast check.** `ghostty_web_abi_version() -> u32` returns `major << 16 | minor`.
- **Manifest.** `ghostty_web_abi_json() -> const char*` uses the same schema as upstream's `ghostty_type_json` (struct sizes, field offsets, enum values) plus `web_abi: { major, minor, features[], ghostty_commit, patch_sha256 }`. The build script stamps the commit and patch hash, because current `ghostty_type_json` reports `commit: null` in our build (03 §6.2).
- **Rules.** `major` changes on any layout or semantic break; `minor` on additive changes. The adapter accepts exactly one `major` and a minimum `minor`, and throws before creating any terminal on mismatch (03-T1). This catches a stale cached or CDN WASM paired with new JS (WEB-15).
- **Feature names.** `events.v1`, `frame.v1`, `colors.tagged`, `modes.snapshot`, `viewport.scroll`, `reset.inplace`, `scrollback.lines`, `links.key`, `selection` (libghostty-vt only at first), `snapshot` (libghostty-vt only).
- **libghostty-vt backend.** Derive the same capability set from export presence, [`ghostty_build_info`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/include/ghostty/vt/build_info.h#L53-L126), `ghostty_type_json` and the build-stamped SHA. `-Dvt-features` subsets remove exports, so presence checks are mandatory; for example `grid_introspection` is required for hyperlink URIs ([C `lib_vt.zig#L369-L413`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/lib_vt.zig#L369-L413)).

### 5.2 Memory and lifetime contract

Adopt 03 §6.3 rules M1–M8 unchanged. The ones that change code today are:

- **M1:** re-acquire `memory.buffer` after every export call (fixes WEB-05's detached `DataView`).
- **M2:** borrowed regions are valid until the next mutating call or the next frame; the frame header carries `seq` and decoders assert it.
- **M3:** one `update` per frame; no getter updates implicitly.
- **M6:** every call returns a result code, and `write` reports a sticky processing-error flag instead of silently dropping the rest of the chunk (patch `catch return`, WEB-15).

### 5.3 Event contract (`events.v1`)

- **Pinned transport.** The handler appends records to a per-terminal buffer during `write`. `ghostty_web_events(term, &ptr, &len)` and `ghostty_web_events_clear(term)` drain it once per write.
- **Record.** `u16 type, u16 flags, u32 len, payload`, padded to 4 bytes.
- **Types.** `PTY_REPLY`, `BELL`, `TITLE`, `PWD`, `CLIPBOARD_WRITE`, `CLIPBOARD_READ_DENIED`, `NOTIFICATION`, `PROGRESS`, `MOUSE_SHAPE`, `SYNC_OUTPUT` (begin/end), `MODE_CHANGED` (for 1004, 2004 and mouse modes, so JS can do host duties such as the focus report on enable), `RESET`, `COLORS_CHANGED`.
- **libghostty-vt transport.** Effect callbacks via function-table trampolines push into the **same JS-side queue**, so everything above the adapter sees one stream.
- **Ordering.** Records arrive in stream order. JS forwards `PTY_REPLY` payloads to the transport in order before dispatching UI events from the same write.
- **Bounds.** A per-terminal byte cap with an overflow counter; `TITLE`/`PWD` coalesce (last wins) and `BELL` coalesces to a count.
- **Synchronous exceptions** (06 V-04, 03 §6.6):
  - **Clipboard read.** The decision must be made at parse time to keep reply order. Default **deny**, which replies with an empty `OSC 52` as current does when denied (05 probe C01). Optionally, JS may register a held value beforehand (pinned: a `ghostty_web_set_clipboard_reply` setter; current: answer inside the callback from that value). Never answer late from `navigator.clipboard.readText()`: that reorders replies. Native's default `clipboard-read = ask` ([P `Config.zig#L2058`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/config/Config.zig#L2058)) cannot be matched synchronously in a browser [C].
  - **Render hold.** On pinned, JS reads the `SYNC_OUTPUT` record or header bit and stops calling `frame`. On current, `RENDER_HOLD` requires updating the render state inside the callback at hold start ([C `terminal.h#L1638-L1756`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/include/ghostty/vt/terminal.h#L1638-L1756)), so the adapter exposes one synchronous hook.
- **Acceptance.** One write containing `OSC 52;c;?` followed by `CSI c` yields replies in that order; a title split across writes gives one `TITLE`; BEL inside OSC gives no `BELL`; overflow increments the counter (03-T14).

### 5.4 Frame snapshot contract (`frame.v1`)

- **Pinned transport.** `ghostty_web_frame(term, flags, &out)` performs exactly one `RenderState.update` and fills a terminal-owned contiguous buffer with: header, row records (which double as the dirty list), 24-byte cells, a grapheme side table, the palette (only when changed) and a string pool. `ghostty_web_frame_clean(term)` runs after drawing; dirt accumulates across undrawn frames, as upstream does.
- **Header.** Sized struct, ABI version, `seq`, dirty level (none/partial/full), active screen, cursor (position, visual style, blink, visible, wide tail, password), tagged default fg/bg/cursor colours, scrollbar `{total, offset, len}`, mode snapshot bits, mouse shape, offsets.
- **Cells.** Codepoint plus width class and has-grapheme bit; tagged fg/bg/underline colour (default, palette index or RGB); attributes including underline style and overline; a 32-bit link key derived from the same fields as [`PageEntry.eql`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/hyperlink.zig#L161-L186). Clicks always re-read the URI at the cell, so a key collision can only mis-highlight a hover.
- **Row ids** use the page serial and page-local y. They are cache keys only: reuse a cached row only if the id matches **and** the row is not dirty.
- **libghostty-vt transport.** JS assembles the same `Frame` from `row_iterator_next_dirty`, `ROW_DATA_CELLS_RAW` plus a per-row style cache (style ids are page-local, SW-09), `DATA_CURSOR`, `DATA_COLORS` and `DATA_SCROLLBAR`, read in the same turn ([C `render.h#L446-L460`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/include/ghostty/vt/render.h#L446-L460)). Link keys come from URIs of `has_hyperlink` cells or from a residual export.
- **Scope.** The frame is an internal contract between the adapter and the renderer, not public API. A packed resolved-row export (04 §7) stays deferred until B3/B4 show extraction matters.

### 5.5 Session snapshot (serialise and restore)

This is deferred and libghostty-vt only, as a `snapshot` capability over `ghostty_snapshot_*` (02 §7), for reconnect and addon parity. Pinned has no equivalent beyond the formatter; do not build one at pinned.

### 5.6 Compatibility and rollout

- **Public surface.** The xterm.js-compatible `Terminal` API and the addons follow npm semver. The WASM ABI is **private** to the package: JS and WASM ship together, and the handshake only guards against mismatched artifacts. Mark `term.wasmTerm` and `GhosttyTerminal` internal in docs, because AGENTS.md currently suggests poking them.
- **User-visible behaviour changes** each get an option, a documented default and a changelog entry: scrollback in approximate lines with `0` = none (WEB-02), scroll-on-output policy (native default is keystroke only, [P `Config.zig#L837`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/config/Config.zig#L837)), a platform keymap for Ctrl+V and copy, a link handler and allow-list, `onUnsafePaste`, and Shift to override mouse capture. The maintainers decide whether each default follows native or xterm.js (open question 5).
- **Two backends during the transition.** The libghostty-vt WASM is built in CI as a separate artifact behind an experimental option and is not in the default bundle until G1–G7 pass. After the default switches, keep the pinned backend for one release as a fallback, then delete it.
- **Legacy exports.** Keep today's exports until the adapter switches over (P2-10), so every PR stays independently shippable.

**Rules** (from 03 §10 and 04 §9):

- Setup stays outside the timed region; warm up first; take at least 7 runs (or at least 40 frames); report median and p95 with raw JSON.
- Interleave backends; prove equal work with checksums; record engine, version, GPU string, DPR, fonts and machine load.
- Never compare a per-cell API with a bulk API that has a different decode target.
- Report frequency × cost for the WEB-01/09/10 effects.

**Proposed targets** (to validate, not claims): zero WASM calls per animation frame when idle with no blink; exactly one update per drawn frame; zero `resize()` calls in 10 idle frames at fractional DPR; one-row partial-frame data path ≤ 10% of a full frame at 200×50; under 1 MiB linear memory per additional filled terminal after migration.

### 7.2 Differential VT correctness

- **Engines.**
  - **E1:** the shipping pinned + patch WASM.
  - **E2:** pinned v2 as it lands.
  - **E3:** current libghostty-vt WASM at the recorded SHA.
  - **E4:** the same libghostty-vt SHA built as a **native** library, to separate WASM-only defects (the RT-01 class) from core semantics. A native library build has not been attempted, so E4 is a gate.
- **Host replies.** Replies that native Ghostty produces in `termio` (for example the focus report on 1004 enable) are checked against expectation tables written from `termio/stream_handler.zig`, because the native app is not part of the differential run.
- **Observables** after every chunk: plain text of the active screen and scrollback; per cell, the grapheme, width class, tagged fg/bg/underline colour and attributes; cursor position, style and visibility; the mode bitset; scrollback row count; title and pwd; reply bytes; the effect log.
- **Chunking invariance.** Whole, bytewise and seeded random splits must give identical observables (05 probe C07 showed this on current).
- **Corpora:**
  - 02's four corpora and 04's Unicode corpus;
  - recorded sessions (vim, htop, tmux, less, `git log --color`) stored as byte files;
  - vttest/esctest-derived sequences (check licences first);
  - a seeded, grammar-aware fuzzer over CSI/OSC/DCS parameters.
- **Triage labels.** `pinned-bug(<upstream sha>)`, `host-policy`, `wasm-only`, `intended-web-divergence`, `new`. CI fails only on `new`. Each `pinned-bug` label names the backport or migration that removes it.

## 9. Risks and what not to do

| Risk                                                                             | Likelihood / impact | Mitigation                                                                              |
| -------------------------------------------------------------------------------- | ------------------- | --------------------------------------------------------------------------------------- |
| Upstream C API churn after migration                                             | High / medium       | pin a SHA; generated bindings; backend matrix and differential CI; small residual       |
| Pinned v2 effort is thrown away                                                  | Certain / medium    | cap scope (I-08 only by default); checkpoint C1 before I-09                             |
| Latent pinned-core bugs become reachable as more state is exported (SW-02/03/04) | Medium / high       | avoid `scroll(.row)` and `linkCells`; backports; stimulus runs on a ReleaseSafe build   |
| `ReleaseSmall` hides corruption (SW-01 was silent)                               | Medium / high       | nightly ReleaseSafe build running the stale-row, resize and prune stimuli               |
| Single-engine, software-GPU numbers mislead the renderer choice                  | High / medium       | B4/B5 across engines with a hardware GPU before any Stage 1–3 decision                  |
| WASM size regression at migration                                                | Certain / medium    | G6 budget agreed early; feature subset; transfer compression                            |
| JSC decode cost on libghostty-vt full frames (0.54–0.70 ms in JS harnesses)      | Medium / low        | typed-array decoding, style cache; packed export only if B3/B4 justify it               |
| Behaviour changes break embedders                                                | Medium / medium     | options, changelog, semver                                                              |
| Real-device input/IME coverage remains incomplete (05 §6)                        | Certain / medium    | validate layouts, composition and browser policy on real devices before input PRs merge |
| Trap isolation across terminals unknown (one probe)                              | Low / high          | poison and recreate; consider instance-per-terminal after migration                     |

**What not to do:**

1. **Do not port** upstream `src/terminal/c/*.zig` to pinned. It depends on post-pinned `RenderState` machinery (03 §7.1).
2. **Do not export** pinned `linkCells` (SW-03) or unpatched `PageList.scroll(.row)` (SW-02).
3. **Do not use the per-cell C API** in the render loop. It costs 15–20× a bulk read (02 §9.2).
4. **Do not step to v1.3.1.** The patch does not compile there and the tag lacks the RT-01, SW-01 and SW-02 fixes (V-02).
5. **Do not rely on `macos_option_as_alt`** in WASM (V-05).
6. **Do not queue clipboard reads** to answer later (V-04).
7. **Do not drop the `Screen.zig` hunk** in the backport PR, or without the P2-11 gate.
8. **Do not grow the pinned patch** into selection, search, snapshots or gestures unless C1 concludes that migration is more than a release cycle away.
9. **Do not build Worker, WebGL2 or packed exports before a measured need.** Do not make a Canvas2D `drawImage` atlas the default; it was the slowest strategy measured (04 RT-13).
10. **Do not compile** HarfBuzz/FreeType or Ghostty's font stack to WASM, and do not adopt the upstream `web_canvas` face (04 §11).
11. **Do not treat happy-dom tests as evidence** of visual, IME or latency fidelity, and do not present static estimates as benchmarks.
12. **Do not keep invented exports** whose names collide with upstream's differently typed `ghostty_terminal_new`/`ghostty_render_state_update`.
13. **Do not make the WASM ABI public**, and do not change user-visible defaults silently.

## 10. Confidence and open questions

**Confidence.**

- **High:**
  - RT-01's priority and fix;
  - tag status and the v1.3.1 failure;
  - that current upstream builds for WASM;
  - availability of the pinned symbols that I-08/I-09 rely on (checked at source: `initAlloc` `stream.zig:506`, `default_modes` `Terminal.zig:214`, `fromTerminal` `key_encode.zig:53`, `scrollViewport` `Terminal.zig:1429`, `scrollbar` `PageList.zig:2302`, `selectionString` `Screen.zig:2264`, encoder options `encoder.h:87-105`);
  - the textual backport applicability results.
- **Medium:**
  - the pinned-first ordering: it rests on the evidence above but depends on unknown upstream tag timing;
  - the Zig line estimates;
  - every effort size.
- **Low:**
  - the browser frame-time or latency effect of any initiative;
  - the duration of the migration;
  - IME and accessibility effort.

**Open questions.**

1. When will a release tag contain the terminal C API (and require Zig 0.16)? This decides migration timing more than anything else.
2. Does the `420de124f` backport also cover the row-recycling paths that `b31fbc846` fixes (the P2-11 gate)?
3. Will upstream accept hyperlink identity in the render-state API, a `mouse_shift_capture` getter, a runtime platform option for the key encoder, and an async clipboard-read pattern?
4. What WASM size budget do the maintainers accept (G6)?
5. Product decisions: should the defaults be native or xterm.js-like for Ctrl+V, scroll on output and link-hover modifiers? Should embedders be offered an explicit reply override for read-only viewers? P0-16 proposes suppressing replies by default when `disableStdin` is set (05 J10). Should the documented `attachCustomKeyEventHandler` polarity incompatibility (06 §6) stay?
6. Which backwards-compatible demo transport framing should carry `onBinary` without UTF-8 re-encoding or confusing data beginning with `{` for JSON control messages (05 J7)?
7. Which real-device matrix will cover the macOS Option/Command, Windows AltGr, dead-key, mobile and IME questions listed in report 05 §6?
8. Which reference platform (fonts, browser versions) makes pixel goldens deterministic in CI?
