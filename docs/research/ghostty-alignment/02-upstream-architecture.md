## Executive summary

1. **At the pinned commit there is no upstream terminal C API at all, so the local patch is the entire terminal ABI [S].** Pinned `lib_vt` exports 50 symbols: key event/encoder, OSC parser, SGR parser, `paste_is_safe`, one color helper and WASM allocation helpers ([P `src/lib_vt.zig#L105-L158`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/lib_vt.zig#L105-L158)). The patch adds 28 terminal/render exports (the audit's "26" undercounts by two) on top of the Zig core, which _does_ already contain most of what ghostty-web re-implements: viewport scrolling, tracked-pin selection, word/line selection, a formatter, `RenderState` with per-row dirty/selection, `linkCells`, `key_encode.Options.fromTerminal`, default modes and set/unset colors.
2. **Current upstream ships a broad, documented libghostty-vt C/WASM API [S][R].** `src/lib_vt.zig` now has 205 `@export`s ([C `src/lib_vt.zig#L173-L434`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/lib_vt.zig#L173-L434)); our WASM build exposes 188 functions, a growable function table and **no imports**. It covers terminal lifecycle, effects callbacks (PTY replies, bell, title, pwd, clipboard, notifications, render hold, reset), layered default/override colors, byte **and line** scrollback limits, reset-persistent mode defaults, viewport scrolling + scrollbar, an incremental render state (dirty rows, row ids, cursor visual style, selection ranges, bulk per-row cell views), selection (word/line/all/output, gesture state machine) and selection formatting, terminal-state-aware key/mouse encoders, focus/paste/size/mode report encoders, search, snapshots, and a machine-readable type/enum manifest (`ghostty_type_json`).
3. **It builds for the browser today [R].** `zig build -Demit-lib-vt -Dtarget=wasm32-freestanding -Doptimize=ReleaseSmall` with Zig 0.16.0 succeeded in 32 s (846,633 B; 285,349 B gzip -9). The documented "interactive" subset (`-Dvt-features=-all,+render-state,+input-encode,+selection,+formatter,+color`) is 691,226 B (213,397 B gzip -9). Pinned+patch is 423,939 B (124,151 B gzip -9), so adopting current upstream roughly **doubles** the WASM payload before tuning.
4. **Probing the current WASM directly confirms that most audited ghostty-web defects have native upstream answers [R]** (Node and Bun produced byte-identical JSON). Examples: DECRQM, the Kitty keyboard query, XTVERSION, OSC 4/11 queries and CSI 14/18 t all reply (WEB-03); BEL inside OSC 0/OSC 8 does not ring and split/binary titles are reported (WEB-03); `#000000` is a valid default color and a cell's "no explicit background" is distinguishable from explicit black (WEB-04); a line-based scrollback limit works (WEB-02); mode 2027 survives RIS when set as a default (WEB-15); idle frames report no dirty rows and a one-character write dirties one row (WEB-01); the viewport stays put while output arrives and history graphemes render correctly (WEB-09); copy of `中文abc` and soft-wrapped text is exact and the selection survives reflow (WEB-08); wheel encodes to SGR 64/65 and same-cell motion is suppressed (WEB-06); Shift+F5/Shift+Home/Ctrl+V/DECCKM/Kitty encodings are correct (WEB-07); paste converts `\n`→`\r` and neutralizes an embedded `ESC[201~` (WEB-12).
5. **The patch's core `Screen.cursorDownScroll` edit is fixing a real pinned-core bug that current upstream has fixed differently [R].** Re-running the stimulus of `lib/viewport-corruption.test.ts` gives 6 failures in 30 repetitions on pinned + patch _minus_ the `Screen.zig` hunk, 0 on pinned + full patch, and 0 on current upstream with no ghostty-web edits ([C `PageList.zig#L4003-L4022`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/terminal/PageList.zig#L4003-L4022) documents the new zero-state invariant). _(Verification note, [report 06](06-verification.md): backporting upstream's page-zeroing fix `420de124f` at pinned also removes these failures without the `Screen.zig` hunk; see §8.3.)_ The `RenderState` black/`#cccccc` fallback edit is unnecessary once the embedder always sets default colors, which the current API supports explicitly.
6. **Parsing is materially faster in current upstream WASM [M].** Feeding identical 4 MiB corpora in 16 KiB writes, current `ghostty_terminal_vt_write` beat pinned+patch `ghostty_terminal_write` by **1.4×–10.1× in Node (V8)** and **2.0×–4.6× in Bun (JSC)** (ASCII text is the largest win). Static cause: pinned `Stream.nextSlice` falls back to byte-at-a-time parsing whenever `build_options.simd` is false, which it always is on WASM ([P `stream.zig#L517-L524`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/stream.zig#L517-L524), [P `Config.zig#L172-L182`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/build/Config.zig#L172-L182)); current upstream keeps the batched path on WASM and enables `simd128` ([C `stream.zig#L703-L727`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/terminal/stream.zig#L703-L727), [C `Config.zig#L113-L130`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/build/Config.zig#L113-L130)). Browser impact is unmeasured.
7. **Current upstream is not a drop-in replacement [S][M][C].** The API is explicitly unstable and untagged; it needs Zig 0.16 and a different build invocation (the `lib-vt` step used by `scripts/build-wasm.sh` no longer exists); callbacks require function-table trampolines from JS; the per-cell render API is too chatty for a JS hot path (3.2 ms per full 200×50 frame in V8 versus 0.22 ms with bulk `CELLS_RAW` + a style cache, and 0.16 ms for the patch's bulk getter); and there are gaps: no hyperlink identity/`linkCells`, no `RenderState.string()`+cell map, no `mouse_shift_capture`, Kitty graphics disabled on `wasm32-freestanding`, scrollback compression unsupported on WASM.
8. **Recommendation.** Treat current libghostty-vt as the target architecture and the source of truth for the ABI. In the short term, fix ghostty-web's TypeScript and patch defects using **pinned-core** facilities (listed per finding in [§10](#10-highest-value-reuse-opportunities-mapped-to-web-findings)) without inventing look-alike APIs; in parallel, build a thin TypeScript adapter around "render state + effects + encoders" so the backend can move to current upstream (or a future tagged release) with a small residual patch or upstream contributions for the gaps.

- **Build:** `zig build -Demit-lib-vt -Dtarget=wasm32-freestanding -Doptimize=ReleaseSmall` ([C `PACKAGING.md#L126-L177`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/PACKAGING.md#L126-L177); WASM is built as an entry-less executable with `rdynamic` and an exported, post-processed **growable** function table, [C `GhosttyLibVt.zig#L38-L98`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/build/GhosttyLibVt.zig#L38-L98)). - **WASM tuning knobs (upstream guidance, not our measurements):** `simd128` is enabled by default for WASM ([C `Config.zig#L113-L130`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/build/Config.zig#L113-L130)) although `build_options.simd` (C++ SIMD libraries) stays false ([C `Config.zig#L238-L248`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/build/Config.zig#L238-L248)); `-Dvt-features` compiles out feature areas and their escape handling ([C `build_options.zig#L59`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/terminal/build_options.zig#L59)); upstream recommends `ReleaseSmall` for the web and says `ReleaseFast` "measures 10-20% faster" on escape-heavy workloads but needs `wasm-opt --strip-dwarf`. Kitty graphics is force-disabled on freestanding targets because it needs timestamps ([C `build_options.zig#L270-L277`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/terminal/build_options.zig#L270-L277)) [C].
- **Host integration rules:** reacquire `memory.buffer` before every host access because any allocating export may grow linear memory ([C `wasm.h#L39-L48`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/include/ghostty/vt/wasm.h#L39-L48)) — the same hazard as the `KeyEncoder.encode` detached-`DataView` bug (WEB-05); by-value structs are passed as pointers in the wasm32 C ABI (the upstream `example/wasm-vt/index.html` passes `GhosttyFormatterTerminalOptions` by pointer); `ghostty_type_json()` returns the ABI (pointer size, alignment), every public struct's field offsets, packed-cell bit layouts and every enum's values — this is the upstream answer to enum drift (WEB-07): the manifest lists `GHOSTTY_KEY_FN = 146`, `FN_LOCK = 147`, `PRINT_SCREEN = 148`, `PASTE = 175`.
- **Stability story [S]:** the umbrella header still says the API is unstable ([C `vt.h#L10-L11`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/include/ghostty/vt.h#L10-L11)); the C-API contributor rules require opaque handles, sized structs (`size` first field, `GHOSTTY_INIT_SIZED`) and `GHOSTTY_ENUM_MAX_VALUE` sentinels for forward compatibility ([C `src/terminal/c/AGENTS.md`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/terminal/c/AGENTS.md)); the manifest reports `library_version` `0.1.0-dev`. Relevant commits are all on `main` after `v1.3.1`: `302e68fd3` (2026-03-13, `ghostty_terminal_new/free`), `a0d738697` (2026-03-18, C render state), `67d8d86ef` (2026-03-22, `ReadonlyStream` → `TerminalStream`), `cc48312c0` (2026-05-24, selection helpers), `03d5fa268` (2026-07-27, scrollback limits via `terminal_set`), `87f69a12e` (2026-08-14, "much faster vt_write on wasm targets"), `74a233b54` (2026-08-14, faster render state reads on WASM incl. `CELLS_RAW`).

### 2.3 Consequence: rebasing means replacing, not porting

The patch cannot be carried forward mechanically [S]: `Terminal.init` now takes a `std.Io` ([C `c/terminal.zig#L978-L988`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/terminal/c/terminal.zig#L978-L988)), `Stream.nextSlice` is infallible (`void`, [C `stream.zig#L645-L651`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/terminal/stream.zig#L645-L651)), `stream_readonly.zig` no longer exists (renamed and extended to `stream_terminal.zig`), and the exported names the patch invented (`ghostty_terminal_new(cols, rows)`, `ghostty_terminal_write`, `ghostty_render_state_update(term)`, …) collide with **different signatures** in upstream (`ghostty_terminal_new(allocator, *out, cols, rows)`, `ghostty_render_state_update(state, terminal)`). A current-based ghostty-web would consume upstream symbols directly and keep, at most, a small residual patch for the gaps in [§7](#7-capabilities-matrix). Conversely, current API names must **not** be presented as available on the pinned build.

Input travels the other way through the app layer: `Surface.keyCallback` → keybindings → `input/key_encode.zig` with `Options.fromTerminal` ([P `key_encode.zig#L53-L66`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/input/key_encode.zig#L53-L66)); mouse → `Surface.mouseReport` ([P `Surface.zig#L3375`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/Surface.zig#L3375)); wheel policy in `Surface.scrollCallback` (alt-screen + mode 1007 + no mouse tracking → cursor keys honouring DECCKM; else mouse report; else viewport scroll, [C `Surface.zig#L3645-L3718`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/Surface.zig#L3645-L3718)); focus → `Termio.focusGained` ([P `Termio.zig#L636`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/termio/Termio.zig#L636)); paste → `input/paste.zig` encode + confirmation UI.

### 3.2 Inside the core (applies to native, the patch and current libghostty-vt)

- **Stream and parser.** `Stream` couples a `Parser` (DEC/VT500 state machine with CSI/OSC/DCS/APC sub-states) and a UTF-8 decoder. In the ground state it decodes runs of UTF-8 and calls `print`/`execute`; escapes go through `consumeUntilGround`. OSC commands that need heap memory (color set/query, clipboard, long titles) only parse when the stream was created with `initAlloc` ([P `stream.zig#L484-L510`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/stream.zig#L484-L510)) — the root cause of the patch's broken OSC 4/10/11 (WEB-03). On WASM, pinned takes the scalar `for (input) |c| try self.next(c)` path ([P `stream.zig#L517-L524`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/stream.zig#L517-L524)); handler errors propagate out of `nextSlice` and the patch's `write` swallows them, dropping the rest of the chunk (WEB-15). Current upstream's stream is infallible, logs handler errors per action, batches printable runs as `print_slice` and supports continuation tracking for snapshots.
- **Terminal.** `print` ([P `Terminal.zig#L301`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/Terminal.zig#L301)) handles grapheme clustering when mode 2027 is on, East-Asian width (wide + spacer-tail/spacer-head cells), autowrap (sets `Row.wrap` on the wrapped row and `wrap_continuation` on the next) and pending-wrap. `linefeed`/`index` scroll via `Screen.cursorDownScroll` → `PageList.grow`. Modes are a `ModeState` holding both current values and defaults (`Options.default_modes`, [P `Terminal.zig#L206-L247`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/Terminal.zig#L206-L247)); `fullReset` restores the defaults ([P `#L2793`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/Terminal.zig#L2793)). Colors are `DynamicRGB`/`DynamicPalette` values that are **unset by default** and carry a default + override layer ([P `Terminal.zig#L131-L143`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/Terminal.zig#L131-L143)) — so the patch's "`0` means unset" color ABI (WEB-04) is an ABI choice, not a core limitation.
- **Screen.** Owns the cursor (pin + cached `page_row`/`page_cell` pointers + current `Style`/`style_id`), saved cursor, charsets, Kitty keyboard flag stack, selection (stored with **tracked pins**), and hyperlink state. SGR changes intern a style in the current page's ref-counted style set (`manualStyleUpdate`, [P `Screen.zig#L1941`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/Screen.zig#L1941)); extra grapheme codepoints go to the page grapheme allocator/map (`appendGrapheme`, [P `#L1994`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/Screen.zig#L1994)); OSC 8 interns `{id, uri}` in the page hyperlink set/map (`startHyperlink`, [P `#L2043`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/Screen.zig#L2043)).
- **Page.** A single contiguous allocation containing the row array, cell array, `string_alloc`, `grapheme_alloc`+`grapheme_map`, `styles`, `hyperlink_map`+`hyperlink_set` and a page `dirty` flag ([P `page.zig#L84-L145`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/page.zig#L84-L145)). `Row` is a packed `u64` with `wrap`, `wrap_continuation`, managed-memory hints (grapheme/styled/hyperlink), semantic prompt and `dirty` ([P `#L1716-L1810`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/page.zig#L1716-L1810)); `Cell` is a packed `u64` (content tag; codepoint or bg-color-only content; page-local `style_id`; `wide`; `protected`; a **boolean** `hyperlink`; semantic content, [P `#L1812`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/page.zig#L1812)). Styles, graphemes and hyperlink IDs are **page-local**, so a cell is only meaningful together with its page — the reason any ABI that wants hyperlink identity or style needs either a resolution step in WASM (patch, `RenderState`) or a lookup call.
- **PageList, scrollback and reflow.** Pages form a linked list from a memory pool. `grow` either extends the last page or appends/prunes ([P `PageList.zig#L2423`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/PageList.zig#L2423)); pruning removes whole oldest pages once the byte budget `max(explicit_max_size, min_max_size)` is exceeded ([P `#L2395-L2402`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/PageList.zig#L2395-L2402)), where `min_max_size` is enough pages for the active area plus one ([P `#L226-L245`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/PageList.zig#L226-L245)) — hence WEB-02's "every setting gives 1,116 lines". The viewport is `active | top | pin` (tracked `viewport_pin`, [P `#L196-L215`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/PageList.zig#L196-L215)), so a scrolled viewport is anchored to content and survives output and pruning; `Terminal.scrollViewport` ([P `Terminal.zig#L1429`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/Terminal.zig#L1429)) and `PageList.scrollbar` ([P `PageList.zig#L2302`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/PageList.zig#L2302)) exist at the pinned commit. Column changes reflow through `PageList.resize`/`resizeCols` ([P `#L806`, `#L862`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/PageList.zig#L806-L870)), updating all tracked pins (selection, viewport, cursor). Current upstream adds a **line** limit alongside the byte limit; the Zig default stays 10,000 **bytes** (effectively the one-page minimum), which is also what a fresh C-API terminal gets unless the embedder sets limits ([C `Terminal.zig#L281-L292`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/terminal/Terminal.zig#L281-L292)).
- **Selection and formatting (core, pinned).** `Screen.select/selectWord/selectLine/selectAll/selectOutput/selectionString` ([P `Screen.zig#L2221-L2700`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/Screen.zig#L2221-L2700)) and `formatter.zig` (`TerminalFormatter`/`ScreenFormatter`/`PageListFormatter`, plain/VT/HTML). Pinned word boundaries are a hard-coded list ([P `#L2533-L2556`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/Screen.zig#L2533-L2556)); current upstream makes them configurable natively (`selection-word-chars`) and in the C API (`boundary_codepoints`).

### 3.3 Render state and renderer

`RenderState` is deliberately in `src/terminal` "to remain generic to multiple renderers … [and] aid … libghostty-vt" ([P `render.zig#L19-L22`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/render.zig#L19-L22)). `update` ([P `#L262-L648`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/render.zig#L262-L648)):

1. Decides on a **full redraw** if the active screen changed, any `Terminal.flags.dirty` or `Screen.dirty` bit is set (including `selection`), the dimensions changed, or the viewport pin moved (L269-303).
2. Copies cheap global state every time: rows/cols, cursor position/cell/style/**visual style**/password-input/visible/**blinking**, cursor color, palette, and fg/bg (swapped under reverse video; left unchanged if the terminal colors are unset, L305-339).
3. Walks the **viewport** rows; for each row, records the pin and — only if the row is dirty (redraw, dirty page, or dirty row) — clears the dirty bit, bulk-copies raw cells and, if the row has managed memory, resolves styles and duplicates graphemes into a per-row arena (L395-552).
4. Computes per-row selection ranges with a cache (L566-628), then sets `dirty = full|partial`, and clears `Terminal.flags.dirty`, `Screen.dirty` and the last dirty page flag (L630-647).

The native renderer calls it once per frame under the terminal mutex, then does links, highlights and cell building outside the lock ([P `generic.zig#L1133-L1272`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/renderer/generic.zig#L1133-L1272)). Current upstream splits `update` into `beginUpdate` (needs the terminal) and `endUpdate` (render-state-only work), adds `clean`, overscan for smooth scrolling and stable row ids ([C `render.zig#L481-L1022`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/terminal/render.zig#L481-L1022)).

Two pinned-core details matter for reuse:

- **`linkCells` has a row-index defect at the pinned commit [S].** It indexes the page with the viewport `y` instead of the row pin's `y` ([P `render.zig#L820-L825`, `#L851`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/render.zig#L820-L851)); current upstream uses `link_pin.y`/`pin.y` ([C `render.zig#L1295-L1300`, `#L1327`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/terminal/render.zig#L1295-L1327)). Any pinned-based export of `linkCells` must backport that fix. Not reproduced (would require a page-spanning viewport probe).
- **`string()` + `StringMap`** produce viewport text with a byte→cell map and soft-wrap joining ([P `render.zig#L745-L793`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/render.zig#L745-L793)); native URL detection runs regexes over this string ([P `renderer/link.zig#L57-L100`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/renderer/link.zig#L57-L100)). Neither is exposed by the current C API.

### 3.4 ghostty-web's path, and the root divergence

ghostty-web (see the [audit's data-flow diagram](01-web-audit.md#data-flow-as-implemented)) writes bytes through `Stream(ResponseHandler)`, drains a response byte buffer by polling, and renders by calling `ghostty_render_state_update` and then `ghostty_render_state_get_viewport`. The decisive detail is that the patch's viewport getter **does not read the viewport and does not read `RenderState`**: it re-walks `pages.pin(.{ .active = … })` rows and re-resolves styles (`patches/ghostty-wasm-api.patch` L1028-1146). Because the ABI can only ever return the active area, ghostty-web had to build its own scroll position, history fetches, grapheme lookups and selection coordinates in TypeScript (WEB-08/09), and because the getter ignores dirty data, the renderer re-decodes the full screen per row (WEB-01). Meanwhile Ghostty's own viewport pin, selection pins and per-row cache already exist in the same WASM module.

**Browser mechanics [R][C].** A C function pointer in WASM is an index into the exported `__indirect_function_table`. JavaScript functions cannot be stored there directly; the probe host generates a tiny WASM module per signature that imports the JS function and exports a defined forwarding function, then `table.grow(1)` + `table.set(idx, fn)` and passes `idx` to `ghostty_terminal_set` (`probes/upstream/vt.mjs`). This worked identically in V8 and JSC. Each callback crossing is a JS↔WASM transition per event, which is fine for replies/bell/title but argues for buffering in JS and flushing once per `write()`.

### 5.2 Dirty layers and who consumes them

```text
producers (VT actions, resize, scroll, selection, color changes)
  Terminal.flags.dirty {palette, reverse_colors, clear, preedit}      ─┐  "global" → full rebuild
  Screen.dirty {selection, hyperlink_hover, …}                          ─┤
  viewport pin moved / screen switched / size changed                   ─┘
  Page.dirty (whole page)  +  Row.dirty (per row)                       → partial rebuild of those rows
        │
        ▼  RenderState.update  (CONSUMES: clears row/page bits as rows are copied, clears
        │                       Terminal.flags.dirty and Screen.dirty at the end, P render.zig#L630-L647)
RenderState.dirty ∈ {false, partial, full}  +  row_data[y].dirty   (sticky; NOT cleared by update)
        │
        ▼  renderer draws rows with dirty=true (all rows if full), then cleans both layers
           (patch: ghostty_render_state_mark_clean; current: ghostty_render_state_clean)
```

Rules that follow [S]:

1. **Exactly one consumer per terminal.** Because `update` consumes terminal-side bits, two render states (or the patch's hidden getters plus a second consumer) would steal each other's invalidations. The current C API allows creating several render states from one terminal; ghostty-web should keep a single owner.
2. **Overlay state is the renderer's job.** Selection changes force a full rebuild at the pinned commit (any `Screen.dirty` bit → redraw); hover/cursor-blink overlays are not terminal dirt. The audit's "re-render every selected row every frame" (WEB-01) disappears if the renderer diffs its own overlay state and relies on `RenderState` row dirtiness for content.
3. **Viewport scroll ⇒ full dirty.** Measured on current upstream: after `scroll_viewport(DELTA, -3)` the state is `FULL`; after output while scrolled up, the viewport offset stays put (13→15 total rows, offset 5) and the next update reports `FALSE` (no visible change) [R]. Stable row ids let a renderer reuse cached row bitmaps across scrolls even though rows are conservatively marked dirty.
4. **Idle frames are free.** Measured on current upstream: a second `update` with no input reports `FALSE` and no dirty rows; writing one character reports `PARTIAL` with only the cursor row dirty [R]. The pinned `RenderState.update` has the same algorithm; ghostty-web's idle cost comes from the patch's getters and the TS loop (WEB-01), not from Ghostty.

### 5.3 Proposed frame lifecycle (applies to either backend)

1. `write(bytes)` → parse → effects collected into JS queues (replies flushed to the socket in order, bell/title/pwd dispatched) → schedule a frame **only if** something changed or an effect asked for it.
2. On the frame: (if not render-held) one `RenderState` update; read global dirty, cursor (visual style, blink, wide tail, password), colors (palette, default fg/bg, cursor color) once; iterate **dirty rows only**; for each row read cells in bulk and per-row selection range; draw; `clean`.
3. Read scrollbar/viewport state in the same turn as the update (current: `GHOSTTY_TERMINAL_DATA_SCROLLBAR`, documented as amortized O(1) and meant to be polled per frame, [C `terminal.h#L2488-L2505`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/include/ghostty/vt/terminal.h#L2488-L2505)).
4. Stop the rAF loop when nothing is dirty and no blink/animation is pending.

### 8.3 Stale rows after scroll growth (patch `Screen.zig` edit)

Stimulus: the 103,244-byte payload of `lib/viewport-corruption.test.ts`, written 30 times into a 160×39 terminal with a 10,000,000-byte scrollback, comparing each row to the first repetition and checking for merged `R00Lnnn` markers (`stale-row.mjs`).

| Build                                                       | Failures / 30 repetitions                                        |
| ----------------------------------------------------------- | ---------------------------------------------------------------- |
| pinned `5714ed07` + patch **without** the `Screen.zig` hunk | **6** (first at rep 4: blank row 34 shows stale `R00L062 ****…`) |
| pinned + full patch (ghostty-web's WASM)                    | 0                                                                |
| current `8f0dd370`, no ghostty-web edits                    | 0                                                                |

Static cause at pinned: `PageList.grow` extends the last page without clearing the newly exposed row ([P `PageList.zig#L2423-L2432`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/PageList.zig#L2423-L2432)) and `cursorDownScroll` clears only when the cursor has a background color ([P `Screen.zig#L853`](https://github.com/ghostty-org/ghostty/blob/5714ed07a1012573261b7b7e3ed2add9c1504496/src/terminal/Screen.zig#L853)). Current upstream keeps the same conditional clear ([C `Screen.zig#L1060`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/src/terminal/Screen.zig#L1060)) but guarantees that rows in unused page capacity are always zeroed because whatever retires a row resets it (`Page.resetRow`; commit `b31fbc846`, 2026-08-25, "terminal: fully reset row metadata when recycling row storage"). The patch's edit is a valid fix for the pinned core and should be **dropped** on rebase; it should also be offered upstream only if a pinned-era maintenance branch matters.

_Verification note ([report 06](06-verification.md)): a build of pinned + patch **without** the `Screen.zig` hunk but **with** the backport of upstream `420de124f`, which zeroes page buffers on freestanding, gave 0/30 failures in two runs of this stimulus. `lib/viewport-corruption.test.ts` and all 356 `lib/` tests passed against that WASM, and the same test fails without the backport. For this stimulus the stale rows therefore come from recycled, un-zeroed page memory, the same root cause as [report 04](04-rendering-and-text.md) RT-01. The upstream backport covers it without a local `Screen.zig` divergence. Whether `b31fbc846` (row-metadata reset on recycle) covers other paths that the backport does not was not tested._

## 9. Measurements

### 9.1 VT write throughput (WASM only) [M]

Method (`bench-vt-write.mjs`): 120×40 terminal, default 10,000-byte scrollback in both builds, mode 2027 enabled in both (the patch enables it; current is configured to match). Four generated 4 MiB corpora written in 16 KiB chunks (pre-allocated input buffer; only the write calls are timed); 1 warm-up + 7 measured runs, fresh terminal per run, median reported. `bench-sanity.mjs` confirmed identical final cursor positions for every corpus.

| Corpus (4 MiB)                                        | Node 22.19 (V8): pinned+patch → current, MiB/s | ratio | Bun 1.2.15 (JSC): pinned+patch → current, MiB/s | ratio |
| ----------------------------------------------------- | ---------------------------------------------- | ----- | ----------------------------------------------- | ----- |
| ASCII lines (`…quick brown fox…\r\n`)                 | 77.3 → 783.3                                   | 10.1× | 84.3 → 384.0                                    | 4.6×  |
| SGR-heavy (10 × `CSI 1;38;5;n m` segments/line)       | 52.1 → 98.1                                    | 1.9×  | 36.3 → 85.9                                     | 2.4×  |
| UTF-8 mixed (CJK, Hangul, emoji + skin tone, accents) | 82.7 → 184.4                                   | 2.2×  | 87.0 → 172.5                                    | 2.0×  |
| Cursor-addressed (`CUP` + SGR + `EL`, htop-like)      | 64.7 → 90.4                                    | 1.4×  | 38.8 → 77.7                                     | 2.0×  |

Run-to-run spread was small (e.g. Node ASCII 51.5–51.9 ms vs 5.0–5.3 ms; Bun SGR 108.6–116.1 ms vs 45.4–50.0 ms). **Attribution is static, not isolated:** the current build differs in parser path (batched `print_slice` instead of per-byte on WASM), `simd128`, handler implementation, compiler (Zig 0.16 vs 0.15.2) and thousands of other commits. The results establish that the upstream VT engine is not the bottleneck it is at the pinned commit; they do not predict ghostty-web frame rates.

### 9.2 Full-frame extraction cost [M]

Method (`bench-frame-extract.mjs`): 200×50 terminal; each iteration writes a full screen of new 256-color fg+bg text (untimed), then times "update the render data and decode codepoint + resolved fg + resolved bg for all 10,000 cells into typed arrays"; 200 measured frames after 10 warm-up, median; each runtime run twice. All three decoders produced **identical** arrays for the final frame.

| Decoder                                                                                                                                                     | Node (V8) median ms | Bun (JSC) median ms |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- | ------------------- |
| pinned+patch: `render_state_update` + one `get_viewport` (16 B/cell) + JS decode                                                                            | 0.161 / 0.162       | 0.150 / 0.149       |
| current A: render state + per-cell API (`cells_next`, `GRAPHEMES_LEN`, `GRAPHEMES_BUF`, `FG_COLOR`, `BG_COLOR`)                                             | 3.206 / 3.323       | 2.330 / 2.302       |
| current B: render state + `ROW_DATA_CELLS_RAW` per row + per-row `style_id` cache (`select` + `STYLE` once per distinct style) + palette from `DATA_COLORS` | 0.220 / 0.222       | 0.705 / 0.696       |

Interpretation: per-cell C-API calls cost ~15–20× a bulk copy, so a JS renderer must use the bulk raw view and resolve styles in JS (the path upstream added for "embedders with expensive call boundaries", [C `render.h#L446-L460`](https://github.com/ghostty-org/ghostty/blob/8f0dd3709050b1026f6324368805033197d8b4a5/include/ghostty/vt/render.h#L446-L460)). Even then JSC was ~4.6× slower than a single bulk copy in this test, which motivates (optionally) a **packed resolved-row export** in a residual patch or upstream proposal. These numbers are per **full** frame; with dirty-row iteration typical frames touch far fewer rows. For comparison, the audit counted up to 51 full-viewport decodes per forced frame in ghostty-web (WEB-01), so fixing the TypeScript call pattern matters more than any of these per-decode differences.

## 12. Browser and platform constraints that remain

- **[C] Single-threaded by default.** All callbacks are synchronous inside `vt_write`; parsing large chunks blocks input and rendering. Upstream's two-phase render update and snapshot API make a Worker-hosted terminal feasible (terminal + parsing in a Worker, rendering via `OffscreenCanvas` in the same Worker, or row data posted to the main thread), but shared-memory threading needs cross-origin isolation (COOP/COEP). Unmeasured.
- **[C] Linear memory.** One module instance shares one 32-bit heap across all terminals; memory never shrinks; scrollback compression is unsupported on WASM [R]; use `DATA_MEMORY_USAGE` to enforce budgets.
- **[C] Function-pointer callbacks** require JS-side trampolines and a growable table (upstream post-processes the table to be growable).
- **[C] No secure randomness or clock on `wasm32-freestanding`:** Kitty clipboard paste events need `GHOSTTY_SYS_OPT_RANDOM_SECURE` (wire to `crypto.getRandomValues`); Kitty graphics is compiled out.
- **[C] Clipboard, notifications, primary selection, `window.open`:** permission- and gesture-gated in browsers; effects give the embedder the decision point but not the capability.
- **[C] Fonts and shaping:** native glyph quality (procedural box drawing, HarfBuzz shaping, sprite atlas) lives in `src/renderer`/`src/font`, outside libghostty-vt; the render state supplies data, not pixels.
- **[D] API churn:** current C API is explicitly unstable; budget for regeneration of bindings from the manifest and a load-time `ghostty_build_info` check.

## 13. Confidence and open questions

**High confidence:** pinned vs current API inventory and build commands (built and inspected both); every behaviour in [§8](#8-verifying-current-upstream-behaviour-against-the-audited-defects) (reproduced in two engines); the stale-row reproduction; the existence and location of pinned-core facilities in [§7](#7-capabilities-matrix) (read at source). **Medium:** attributions of the throughput gain (static reasoning; not isolated); recommendations on frame decode strategy (WASM-only measurement, no canvas). **Low / unverified:** browser frame times, memory behaviour under long sessions, IME/keyboard layout interactions with the key encoder, `linkCells` pinned defect impact (static only).

Open questions for later specialists or upstream:

1. When will the terminal/render C API appear in a tagged release, and is there an ABI freeze plan beyond `ghostty_type_json`?
2. Would upstream accept (a) a render-state `linkCells`/hyperlink-id export, (b) a `mouse_shift_capture` getter, (c) a packed "resolved row" export for high-FFI-cost embedders?
3. Should the documented line-limit semantics ("almost always higher") be corrected given the observed shortfall of up to a page?
4. What is the browser frame cost of a Canvas2D/WebGL renderer fed by dirty rows from `CELLS_RAW` versus the current renderer? (Needs a Playwright harness with DPR 1/1.25/2, 80×24 and 250×70.)
5. Is `ReleaseFast` + `wasm-opt --strip-dwarf` worth its size in browsers for ghostty-web's workloads (upstream claims 10–20% on escape-heavy input)?
6. Does a Worker-hosted terminal (with `render_hold` and two-phase updates) reduce input latency under heavy output enough to justify the complexity?
7. Can Kitty graphics be enabled on WASM via `sys` callbacks for time and image decoding?
